## 1. 阶段一 · Agent 收敛包（叙事：受控）

> 目标：让模型不乱来、不绕圈，回合数从 6–10 压到 2–3。

### 1.1 [ ] 显式阶段状态机 + 越权工具拒绝
- 目标/做法：把 capture → analysis → approve 的阶段约束从「提示词」升级为显式状态机；每阶段只放行对应工具，跨阶段调用直接拒绝并返回结构化提示让模型自纠。
- 加分点：面试必问“你怎么保证 Agent 不乱来”，这是比提示词更硬的答案；实现量小（一张阶段→工具矩阵）。
- 工作量：0.5–1 天
- 验收：fake provider 注入“跳阶段调用”被拒绝，事件流里留下越权记录，run 不崩溃。

### 1.2 [ ] 同一步内工具调用去重 / 防绕圈
- 目标/做法：同一 (step, 工具) 已成功过就不允许再调；重复调用返回“结果未变化”并计入异常（直接治 `read_request`×4）。
- 工作量：0.5 天
- 验收：同一步重复调用被拦截，报告显示重复调用次数；真实/模拟回合数下降。

### 1.3 [ ] 人工操作结果直接注入 Agent
- 目标/做法：修正/确认/审批结果作为事件直接注入上下文，模型不再反复 `read_request` 猜状态。
- 加分点：体现 agent 编排理解（结果驱动，而非模型轮询）。
- 工作量：1 天
- 验收：人工复核后 1 个回合内进入分析，回合数显著下降。

## 2. 阶段二 · Agent 可靠性包（叙事：不红）

> 目标：网关/预算异常不再直接红屏。

### 2.1 [ ] length / 0 输出自动重试 + 输出预算放宽
- 目标/做法：`finish_reason=length` 且 0 输出 → 自动重试一次并放宽输出预算；仍失败给中文可操作提示。
- 加分点：现成面试案例「网关偶发截断 → 自动重试 → 不红」。
- 工作量：0.5–1 天
- 验收：注入 length 错误后 run 自动恢复完成；事件流记录 retry 原因。

### 2.2 [ ] 预算/回合感知降级
- 目标/做法：Token/回合预算快用完 → 先自动压缩上下文 → 仍不够 → 停在安全边界并明确告知用户，而非硬失败。
- 加分点：体现「预算也是 agent 治理的一部分」。
- 工作量：0.5–1 天
- 验收：预算耗尽路径产生「已停在安全边界」的明确状态，而不是 failed 红屏。

### 2.3 [ ] Few-shot 示例注入
- 目标/做法：系统提示词给 2–3 条理想工具序列示例（新对话→capture→analysis→等审批）。
- 工作量：0.5 天
- 验收：真实/模拟回合数下降，既有测试无回归。

## 3. 阶段三 · Agent 治理与可观测包（叙事：可查）

> 目标：每个决策可回溯、可解释。

### 3.1 [ ] 工具调用理由记录
- 目标/做法：每回合记录模型“调用工具前的说明”作为 reason 存入事件流，并在报告展示。
- 工作量：0.5 天
- 验收：运行报告显示每次工具调用的理由文本。

### 3.2 [ ] 收敛指标进运行报告
- 目标/做法：报告新增：模型回合数、每个工具调用次数、重复调用次数、越权调用次数、每次调用的理由。
- 加分点：状态机 + 去重 + 跑批的可视化输出，面试直接翻报告说话。
- 工作量：0.5 天
- 验收：报告 JSON/页面含上述指标字段。

### 3.3 [ ] 独立评审最小版（启用现有 `_ai_check`）
- 目标/做法：审批前用第二个 provider/模型交叉验证推荐是否与确定性比价一致，输出 pass/fail + 理由；**不阻塞审批**，只作为证据。
- 加分点：“可治理 agent”叙事的最强证据；代码已有 `_ai_check` 基础，工作量可控（配置化 + 一个演示场景）。
- 工作量：1–1.5 天
- 验收：配置化启用后，审批记录旁出现评审结果（pass/fail + 理由），开关可关。

## 4. 阶段四 · Agent 评测与行为回归包（叙事：可证）

> 目标：从 demo 变 engineered 的硬证据。

### 4.1 [ ] 真实模型验收跑批
- 目标/做法：5–10 个场景，受预算约束跑真实模型；脚本输出：回合数、工具调用数、成功率、Token/成本基线。
- 加分点：面试被问“真实模型行不行”时的答案；从 demo → engineered 的唯一硬证据。
- 工作量：1–2 天
- 验收：脚本可复现；报告含场景级指标 + 诚实分层说明（确定性 617/620 vs 真实模型基线）。
- 阶段验证约定（关键）：**每个阶段全部条目完成后，用真实模型路径（deepseek-v4-flash，`.env` key，受预算约束）复测该阶段改动确实生效**，而不是只靠 fake 测试通过：
  - 阶段一：完整任务跑真实模型，回合数/重复调用较阶段前基线明显下降（如从 6–10 降到 2–3）；
  - 阶段二：复现 length/预算耗尽，确认自动重试/降级生效、不再红屏；
  - 阶段三：运行报告包含工具调用理由、收敛指标、独立评审记录；
  - 阶段四：跑批脚本本身即真实模型基线输出；
  - 阶段五：真实模型下审批 → PO 导出端到端可用。
  每次阶段验证：先记录基线/预期 → 跑真实模型路径 → 记录 run_id/状态/回合/工具调用/Token 成本 → 与预期对比 → 写入 `docs/evidence/stage-<N>-real-model-<日期>.md`。无效则诊断修复（区分模型问题 vs 编排问题），不得用 fake 结果掩盖。

### 4.2 [ ] Agent 行为回归测试集
- 目标/做法：用 fake provider 注入坏行为（跳阶段、重复调用、编造参数、提前声称成功）→ 断言系统拦截/纠正。
- 加分点：agent 行为测试比普通单测更贴 agent 工程。
- 工作量：0.5–1 天
- 验收：新增测试文件全绿，覆盖上述 4 类坏行为。

## 5. 阶段五 · 业务闭环与呈现（叙事：完整）

> 目标：业务最小完整 + 30 秒讲清项目。

### 5.1 [ ] 审批后生成采购订单（PO）导出
- 目标/做法：审批通过 → 生成订单（一个数据表 + 导出 PDF/Excel + 页面按钮）；不做收货/付款。
- 工作量：1 天
- 验收：审批后能生成并下载订单，含供应商/物料/数量/金额/快照引用。

### 5.2 [ ] README：架构边界图 + 健康度表 + 3 个可靠性案例
- 目标/做法：一张架构边界图 + 健康度表 + 3 个「现象→根因→修复→回归」案例。
- 工作量：0.5 天
- 验收：README 30 秒可讲清“交付了什么、怎么证明可靠”。

### 5.3 [ ] 使用层面顺手项（低成本高感知）
- 报错中文化 + 一键恢复入口（不再让用户看 `UNIQUE constraint failed...`）；
- 审批状态文案「等待采购员确认」取代「写入审批 · 执行中」；
- 一键清理/新建演示任务。
- 工作量：0.5–1 天

## 6. 明确不做（实习项目减分项）

ERP/邮件/企微集成、多租户、RBAC/登录、OCR、多语言解析、移动端、RAG、监控看板、K8s、成本控制台——面试用「怎么加回」讲即可（FAQ 已备好）。

## 7. 面试叙事（15 分钟）

1. 架构边界图（2 分钟）；
2. 现场跑通一条链路（3 分钟，`procurement_fake` 确定性演示）；
3. 真实模型跑批结果（2 分钟，诚实讲成功率/回合数/成本）；
4. 一个可靠性案例：现象→根因→修复→回归测试（3 分钟）；
5. 主动讲边界：617/620 是确定性管线 0 模型调用；真实模型基线看跑批报告（3 分钟）。
